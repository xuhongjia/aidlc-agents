# Frame the design question

Follow `core:prompts/common.md` and the core knowledge protocol. Read the bound request, current project evidence and applicable approved knowledge. Define the decision to support, users, scope, constraints, FR/NFR, success criteria, current interfaces and evidence gaps. Distinguish observed facts from hypotheses and user decisions still required.

Write only the declared `analysis` artifact, `decision-brief.md`. Do not edit product files, configure tools, execute operational changes or claim implementation authority. Relevant knowledge must be checked against current project evidence; it is not policy or approval by itself. Return blocked if missing evidence prevents a meaningful bounded study.

The approved brief is the shared baseline for two independent analyses. Do not predetermine the security study's conclusions or present a desired option as an approved decision.
