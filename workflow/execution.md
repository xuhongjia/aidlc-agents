# Execution policy: parent only

0.16 adds optional model selection, read-only helpers, usage receipts and risk cards. No new stage, runner, authentication system or approval. Old locks without execution keep their original method. Existing required checks, original business inputs, real host permissions and approvals still apply.

## Freeze and derive

Resolve config.execution.policy_ref and review_catalog_ref through core/team/project assets. Defaults are [policy](execution-policy.json) and [cards](review-cards.json). Overrides select a complete reviewed JSON resource; never edit the installed core or silently merge unknown fields. Model bindings contain identifiers, not credentials. New lock.execution is `{contract_version:1,policy_ref,review_catalog_ref,validation_ref}`: the first two are namespace refs in assets; validation_ref is a raw-byte `{path,sha256}` reference to frozen structural requirements. Freeze helper modules, catalogs, all cards and their source assets. Only selected cards enter Reviewer instruction_refs; helpers and policy bodies are parent-only.

Policy/requirements changes after approval require new resolution and the existing approval process. Team-defined roles need explicit defaults. Derive the role from the frozen stage/leaf assignment, never a user-document label: Gate leaves use their assigned Reviewer, final collection uses collector, ordinary stages use their locked role. Fixed-content helper applies only to mechanical tasks, not renamed design/approval duties. Parent also accounts for itself. Task/risk assessment cites approved inputs/current code; use one assessment for routing and cards. Workflow name, line count and model confidence are not risk evidence.

The prepare operation resolves policy/request/host. request is `{role,task_tier,risk_tags,required_capabilities}` with optional explicit same-tier fallback_model/fallback_reason. Tier is max(role default, task requirement, risk floors); Reviewer/collector minimum is medium. Unknown role/risk requires assessment/configuration. Role/tasks/risks do not grant permissions. Heavy cannot resolve missing facts or waive human decisions.

enabled=false inherits the host; still record the suggested tier, with capability_verification=unverified and no claimed model. Enabling selection requires an explicit configuration request and actual supported native model selection. Host models supply id/tiers/capabilities/supported reasoning; tier eligibility is the team's reviewed qualification, not a claim that a vendor publishes these tiers. Never infer capability from a model name. Same-tier configured fallback is allowed only for rate_limit/temporarily_unavailable within existing retry authority/budget; authentication, permissions, test failures or missing capabilities never trigger provider switching. Reasoning is independent. No host/global settings changes, alternative CLI or live model probe by default.

dispatch.execution follows [execution-dispatch](../templates/work/execution-dispatch.json). policy_ref/host_ref are raw-byte source references; decision is the actual resolver result; assessment supplies assessed risk_tags/changed_paths/required_card_ids and source refs. Parent verifies full locked files/current host receipts, then uses prepare to join assignment, one assessment, selection and reservations; only prepared permits dispatch. assignment includes kind/run_id/attempt/frozen stage and gate_assignment where applicable. Parent passes the actual native arguments and approved scope; reconcile checks actual model/reasoning/worker against the prepared decision before promotion. Unknown/different actual selection blocks configured selection. Inheritance remains explicitly unverified; missing meters follow budgets.

## Tool checks and direct Verify

Use existing Node and the frozen verified `helpers/check.mjs PROJECT_ROOT REQUEST_RELATIVE_PATH` entry; no dependency installation or inline reimplementation. The [request](../templates/work/helper-request.json) selects validate, prepare, usage, budget, cards, findings, reconcile or verify-plan with hashed JSON parameters; see [operation fields](../docs/helper-usage.md). validate wraps the existing [validation request](../templates/work/validation-request.json). The entry reads complete bytes, without writes, commands, network, approvals or dispatch. Helper source stays out of Agent context. Without Node, retain original host checks and collector path; claim no helper verification or optimized dispatch.

For decision evidence, capture `--full` output once through the host, retaining its exit code and complete envelope; use operation=summary against that saved file for a bounded display (at most 2,048 bytes). Inspect complete blockers/plans before acting; omitted or truncated details never authorize progress. Saved summaries are historical, not fresh preflight or host attestation. Status valid/prepared and zero exit grant neither approval nor Gate PASS; unavailable meters remain unknown.

The [requirements](../templates/work/validation-requirements.json) describe every step's candidate_scope, required_inputs, approval_roles, required_evidence, gate_baselines and qa_required. Build from the full frozen graph/scope/semantic inputs; QA/CI/CD/acceptance sources cannot disappear under an analysis name. Dynamic refs reside in execution.validation: input_refs add contract/producer_step_id and, absent an approved producer file, producer_result_ref; approval_pairs carry role/review_ref/approval_ref; evidence_refs add id; gate_baselines carry kind/ref. Inputs must belong to the producer's review or original result artifacts. Requirements are not a convenient caller subset. candidate_approval_required defaults false: existing execution authority plus a frozen candidate suffices; no new pre-Gate candidate approval. Explicit candidate-bound policies require complete identity matching.

Evidence refs use [structural envelopes](../templates/work/validation-evidence.json), retaining original QA/pipeline reports and logs as raw_refs. checks carry id/executed_count/status/raw_ref; configured pipelines add binding_id/status/collection_status. These envelopes do not replace original formats or semantic verification. [Host checks](../templates/work/host-check.json) bind invocation/dispatch/candidate, observed within 60 seconds: authority, revocation, candidate_scope, input_approvals, semantic_requirements each needs status=confirmed and genuine source_refs. Parent independently authenticates these observations; a locally written confirmation is not authority. The helper validates stage dispatch only; leaf checks retain their existing full host contract.

Direct mode requires verification kind, complete unchanged candidate, approved Architecture/Quality baselines, every required upstream input/approval (including QA where required), collected mandatory CI/CD and a current invocation-bound host receipt. Preflight status valid is not Gate PASS. Failure blocks; running external work waits; incomplete preparation may use a fresh initial collector to gather evidence, never to bypass missing prerequisites.

Before reviewers, reserve a unique future collector run ID bound to work/step/revision/candidate/inputs/rules; store its planned status separately from actual execution. Gate leaves receive that collector_run_id and actual parent dispatch identity. Spawn two distinct independent Reviewers subject to real resource/usage limits, then spawn exactly one independent collector with the reserved ID after both results. Collector validates native worker identity, actual evidence and all AC; parent never writes its conclusions. Do not count a reserved ID as an actual Agent, fabricate a dispatch receipt, or reuse a previous candidate's completed reservation. Original path remains initial collector -> leaves -> fresh collector. Both paths require final approval and unchanged role-team QA ordering.

## Usage and budgets

Use [execution-receipt](../templates/work/execution-receipt.json) for each exclusive run/attempt delta from native evidence. source_ref identifies the precise event/span (for example trace#event-ID), never one whole trace reused across runs. actual_model/reasoning and usage are observed or null. input_tokens includes cached_input_tokens; noncached is their difference only when both exist. Never estimate from bytes, infer actual model from intent, sum cumulative counters as deltas, or count children again in parent totals. Include failures/late attempts/parent/stages/leaves/collectors/Hooks; resume does not reset usage.

Parent verifies and appends immutable receipt refs to state.execution_receipts; result.execution_receipt_ref may point to the same host-backed record. Missing return receipts are still recorded with observed identities and unavailable meters, not omitted from accounting. usage deduplicates identical attempts, rejects conflicting duplicates and separates observed subtotals from unavailable totals. Empty history is not measured zero usage.

Before dispatch/retry/Hook call budget with complete verified history plus outstanding and proposed reservations `{run_id,attempt,executor_id:null|actual_id,kind,calls,retries}`; every Agent reservation needs calls>=1. Pure tools are not Agent dispatches. Reserve atomically as sole parent writer; keep unknown executions reserved. Replace the matching reservation once after a real receipt, including failed starts. Count the complete work. Reserve the authorized call allowance and recheck additional calls where supported; an opaque host loop is not a per-call hard cap.

Configured unknown-meter limits pause by default; explicit unknown_usage=continue produces a visible warning, never an enforcement claim. Known subtotals can still exhaust a budget. Limits stop new dispatch, not already-running calls; tokens/cost are not prepaid hard caps. No automatic tier downgrade, budget reset or retry authority. Tool-output bytes measure returned text, not evidence retention. Cost requires actual provider billing data; none is invented.

## Risk cards and results

Use cards with the same assessment and verified frozen catalog/assets. Route only assigned Gate cards (purpose=review-card) and their source refs (purpose=review-card-source), deduplicating mandatory reads. Copy card identities into dispatch.review_cards and gate-result.review_card_refs. Unknown/unassessed risk returns needs_assessment. No match is not clearance; mandatory rules/team instructions remain. verify-plan turns an explicit current preflight into reserved task dependencies only; it never creates Agents or approval.

findings checks candidate/reference/status structure against approved blocking rules. Read raw evidence independently: schema validity is not truth, confirmed is not automatically blocking, and required inconclusive/missing evidence cannot PASS. Preserve disproved findings and limitations. Reviewer-written tests/repairs remain forbidden; route necessary reproduction to an authorized Implement continuation. No findings means an empty array, not invented examples.
