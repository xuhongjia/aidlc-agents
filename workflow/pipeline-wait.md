# External pipeline waiting: parent coordinator

Handle only waiting_external from already authorized stages or their monitor wakeups. Validate real wait_request/result, dispatch identity, locked delivery and current candidate/inputs/rules. Preserve original runs, then stop/release slots. Waiting creates no review/approval/Gate PASS and does not revoke delegation as execution failure. Real failures retain original approval stop rules.

## Records and host monitoring

state.waits items contain {step_id,revision,request_ref,workflow_ref,candidate_ref,delivery_digest,input_refs,baseline_refs,binding_ids,targets,authorization_ref,started_at,deadline,last_checked_at,last_fingerprint,status}. status=waiting/ready/blocked/canceled/expired/finished. Derive deadline from first wait plus locked timeout; additional wait_requests/resumption/retries never reset it. state.wait_monitor holds actual host {provider,id,status,scope_ref,authorization_ref}. One shared monitor per work covers its currently valid waits.

native_wakeup defaults to 300-second intervals, maximum 7200 seconds. Prefer existing event waits; otherwise use native thread heartbeat/scheduled wakeups. Explicit instructions: read-only inspect only this work's frozen sources within original deadline; stay quiet on unchanged state; notify only first required human action, failure, permission issue, timeout or completion. Never approve/start/retry/cancel pipelines/deploy or create chats. Codex uses host automation_update heartbeat; other hosts first probe actual capabilities. Never substitute OS cron, persistent polling or installed services.

Verify monitor identity by project identity/work path/workflow_ref, never similar names. Pause after earlier waits finish. If later legitimately dispatched nodes wait, update the same verified monitor and that node's first deadline without restarting completed nodes. Create a replacement only when the original host object is proven deleted; at most one active monitor per work. Query unknown states before recreating.

Entry cards explicitly confirm read-only targets/bindings/interval/deadline and “new child collection for the same authorized stage.” state.wait_authorization_ref points to the actual approved card/approval or valid delegation; waits/monitors reuse that frozen ref. Delivery configuration grants none. Without explicit background-wait consent, manual continuation only. Automatic modes additionally require valid original delegation. Before host registration, persist creation intent/stable work identity. Unknown responses require querying existing tasks, never blind duplicate creation. Update existing in-scope monitors with complete fields and preserved notification preferences. Unsupported/failed registration sets monitor.status=unavailable, retains waiting and supplies “continue aidlc WORK” manual instructions; never claim background continuation.

## Each wakeup

1. Load only this protocol, work state/valid authority/frozen wait scope. For closing/closed/completed, revocation, graph/candidate/input drift or expired deadline, first stop/pause the actual monitor and preserve results. Unproven cessation remains stop_pending, never cleaned. Stopping local waiting/monitoring never cancels corporate pipelines.
2. Verify no live worker for the same step/revision and no other coordinator claiming resumption. Without atomic claim/locking, wakeups may query/notify only; dispatch requires explicit continuation, never competing duplicate children. Default capacity remains: pending timers use no slot; resumed children do.
3. Read-only inspect locates latest relevant pipelines, required job states and target deployment versions. Do not download full logs, reload all stages or rerun Gates. Unchanged results/fingerprints update last_checked_at and end quietly. Notify the first manual/blocked state and keep observing within the original deadline. Respect Retry-After without widening the window.
4. When collection is possible or failure evidence needed, apply original-method preflight (existing work retains its version), rights/dependencies/scope, then dispatch a new independent same-stage child with continuation_refs/frozen pipeline_requests. inspect decides resumability only; actual resumed results determine review/blocked/failed. Archive late results without advancing new revisions.
5. After collection mark the wait finished; other waits retain the shared monitor. Stop it when all finish. manual remains awaiting_approval. auto may approve/continue only with complete mandatory evidence and valid delegation. Before publication, recheck latest required jobs/deployments against review. Material changes require new run/review, never old approval edits.

“Stop waiting WORK” stops monitoring and retains waiting, without closing work or granting resumption. Later explicit continuation may resume within the original deadline. Extension records the user's explicit new deadline and retains original time/history. Closure, automatic-mode revocation, graph changes and normal completion clean monitors/resuming workers. Timers without live workers use no capacity; unfinished waiting work still blocks method updates under preflight.

Gate reuse preserves execution lineage/raw sources, validated by same candidate/graph/rules/inputs/evidence digests. Never attach old Gates to current run identities. Refresh mutable sources; missing/truncated evidence cannot be reused. This uses host capabilities only; untested real automatic wakeups are separately NOT_RUN.
