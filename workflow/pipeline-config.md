# CI/CD Interface: contract 1

Missing/null config.delivery means unintegrated; empty bindings are an unconfigured template. See [delivery/config](../templates/delivery/config.json). Stop on unknown provider/contract/report semantics; never guess execution. Credentials stay in host connection refs, never configuration tokens/passwords/secrets.

delivery contains gate_mode=local/ci/hybrid, bindings and wait. local preserves local dual Gates plus all bound mandatory CI/CD validation. ci requires actual CI evidence for every mandatory dual-Gate rule. hybrid selects CI/local evidence per approved rule without repeating still-valid checks; local PASS cannot override required CI FAIL.

## Binding

Freeze these fields per binding:

- id, phase=ci/cd, provider (initially gitlab), connection_ref and project (actual ID/full path).
- apply_to is a selector array of {kind,workflow_ids:[],step_ids:[]}. kind must be verification/release_readiness/learning. Empty ID arrays select all of that kind; nonempty arrays match exactly; selectors form a union. Execute each binding once, not once per matching selector. Stages require evidence.read. Default CI→verification, CD→release_readiness. Compact CD additionally uses kind=verification, workflow_ids=[core.fix,core.enhance], without expanding standard Verify.
- selector={pipeline_id:null,ref:null,sources:[],upstream_binding:null}. Without CI ID, find latest matching pipeline for this candidate's full commit/configured ref/source; sources must be explicit. Locate CD by the same candidate or configured upstream_binding immutable artifacts/upstream source. Explicit IDs still require every constraint check, never implicit trust.
- required_jobs lists exact job names, rejecting duplicate/empty entries. Matrix checks list actual required names, never fuzzy matching. Every job needs reviewable success criteria; stage grouping cannot replace job checks.
- reports is an array of {id,job,artifact_path,format,type,gate_kind?,mapping}. job belongs to required_jobs; artifact_path is safe/relative. format=json/junit, type=gate/artifact/deployment/environment. JSON mapping maps logical fields to actual dotted paths, including explicit nested-array member fields. Extract fields only; execute no expressions/scripts. JUnit retains suites/cases/failures/skips/corresponding job; totals alone prove no rule identity. gate_kind is only architecture/quality, linked to approved rule ID/digest and AC/Oracle. Uninterpretable formats/fields remain unverified.
- environment is null for CI; CD uses {name,required_checks:[]} with exact environment/nonempty smoke/health IDs. Optional observation_tool_binding_ids reference only actual operations already declared by the current Stage and locked with effect=read. Retain extensions operation schema/target/work-level read authority; grant no new rights. Bind inputs to candidate/environment/deployment. Normalize raw responses to source_commit/environment/observed_artifacts/environment_checks and preserve snapshots. Reports may complement queries; never selectively ignore conflicts/duplicates. Without environment reports, explicit queries are mandatory, as is real deployment evidence. CD also declares approval_dependency=none/verify_final; present other dependencies for review in configuration notes. A Verify-bound CD requiring final Verify approval is circular and rejected; use a team release_readiness DAG after approved Verify.

wait={mode:native_wakeup/manual_resume,interval_seconds:300,timeout_seconds:7200}. Interval/timeout are positive integers; timeout covers at least one interval. Automatic waiting has a fixed deadline, never reset by resumption/job retries. The entry card discloses bindings/environment/required checks/report mappings/gate_mode/wait scope/deadline. Background wakeups require explicit confirmation of waiting/same-stage resumption, granting no next-stage continuation.

## Freezing and dispatch

For new work, determine bindings from the core→team→project resolved graph. Reject unknown steps/workflows or inapplicable kinds/capabilities. workflow.lock.delivery freezes the complete actually used configuration, excludes unused bindings and retains actual content digest and {step_id,binding_ids}. Freeze configuration/adapters/conditional protocols/templates unchanged as assets. No bindings means delivery=null. Changed targets/mappings/gate_mode require new graph/work confirmation, never hot replacement.

Each dispatch.pipeline_requests item is {binding_id,binding_digest,phase,candidate_ref,candidate_commit,upstream_binding,expected_artifacts,upstream_result_refs}, matching locked configuration/current approved inputs. dispatch.candidate.ref is the frozen complete-candidate manifest; commit is a verified content-matching full Git commit. external_reads records connection/project/operation scope; actual tools retain frozen tool_bindings/host rights. GET/read-only only; evidence collection cannot start/retry/cancel/approve/deploy.

Resolve expected artifacts from this approved candidate's CI evidence, never fixed old setup digests. For same-step upstreams without results, CD requests freeze upstream_binding with empty expected_artifacts/upstream_result_refs to express dependency. The child obtains CI first, then validates CD against this run's real PASS producer/result/immutable artifacts, preserving derivation without editing dispatch/lock. Upstreams outside this step require verified frozen CI result refs. Without upstream bindings, approved inputs must provide traceable expected artifacts; missing values cannot pass. No source may use invented future PASS.

The interface is resolve (locate), inspect (progress), collect (evidence): a host invocation contract, not a new CLI/service. resolve takes candidate/selector and returns project/pipeline/linkage evidence or gaps. inspect returns raw status, required jobs/attempts, environment/update time. collect uses mappings to save [pipeline-result](../templates/work/pipeline-result.json) and source-index raw snapshots, returning PASS/FAIL/WAITING/UNKNOWN. collection_status describes completeness only, never a pass. Each binding has separate results; all mandatory bindings must pass before review.

Configured environment queries derive pipeline_request.observation_bindings=[{id,sha256}] from full locked ToolBindings. Actual requests/responses must prove that read-only operation and exact inputs, not merely supply an “observation PASS” file. Fields/output contracts follow actual host schemas. Unknown schemas/missing connections stay blocked; never install tools, probe unauthorized environments or alter deployments to satisfy checks.

Stage/tool bindings still validate under extensions. Frozen versions/digests of corporate shared templates/effective job definitions are Gate rule sources; mutable include URLs are not approved rule identities. This package has runtime=none; maintenance test models are not installed payload.
