# 用例、脚本与结果同步 · 按需协议

由显式“同步用例/结果”或 DEV 继续当前工作触发，没有后台监听器。只有启用角色流才读取。源为 Jira 已批准 Story/AC 与 QA 用例；代码库中的快照是版本化实施输入，不是另一个可编辑业务主本。外部写入由父核验后派独立同步 child，执行固定内容，不重写结论；计入现有 worker/停止管理。

## 用例到代码

1. 读取绑定 Story/测试设计 Task 的稳定 ID、当前实际内容/更新时间，与原批准快照逐项比较 Case ID/revision、AC、步骤、数据、预期、required、执行方式；再检查工程侧 script-mapping 的关联。不全库扫描、不按标题配对、不每条用例重新抓一遍 Story。
2. 对文本修正保存“验证语义未变”的真实审阅与两版摘要；新增/移除用例、数据/步骤/预期/覆盖变化生成新 Test Design 基线，旧批准不回填。业务规则/AC 变化必须由 PO 先确认，再由 QA 确认用例；仅 QA 编辑不扩大需求。
3. 将受影响脚本标待同步，历史结果保留其旧版本/候选，不能用于新基线通过。原稿尚未批准、存在编辑冲突或撤销时，只有差异分析，不修改代码。
4. 父按现有 DAG 失效链预约新的 Implement revision，取得原规则要求的实施授权；只有软件工程师在 implementation/product.write 内修改相应单元/集成/UI 脚本、fixture 或代码。保留手工内容，生成最小可审查变更；没有适用自动化映射的人工项明确保留，不生成恒真脚本。非零纠错预算不会因同步自动增加。
5. 真正运行受影响测试、必要回归并冻结新候选；需要 QA 的项重新执行。旧 QA/Gate 不改 hash 冒充新结果。图/权限/目标变化需新图与授权；普通同步不自动 push/MR/merge、部署或触发 CI。无源码权限的 QA 交同步请求，由 DEV 继续执行。

## 发布到 Jira

使用 [Jira adapter](../adapters/collaboration/jira.md) 和 [sync-receipt](../templates/collaboration/sync-receipt.json)。普通 Task 实现的是 AIDLC 约定，不假称 Xray/Zephyr 等测试管理能力。业务用例正文可读；生成的单元测试细节留仓库。一轮测试结果 Task 记录 Case ID+版本、候选 commit/构建物、环境、数据版本、执行者/时间、实际结果和证据链接。覆盖同一 Case 的多轮执行保留独立记录，不覆盖历史 PASS/FAIL。

工作级 [authorization](../templates/collaboration/authorization.json) 必须包含真实决策来源、精确项目/Story 或已批准创建意图、允许的 create/update_owned/link/attach 操作、目标与固定发布内容。没有授权先准备可审查变更，待决定；已有有效范围内授权直接执行，不重复逐条询问。角色批准不是自动写权限；知识发布授权不能复用。创建新 Story 尚无 issue ID 时使用已批准的 PRD/Story 草稿 ID+摘要，读回真实 ID 后建立映射；不以空 story_ids 表示通配全项目。

写前保存固定输入/目标/授权/幂等键与 attempt；幂等键由项目、来源 work/Story、产物逻辑 ID、内容版本和目标决定，同内容重试不换键。更新仅限有创建回执或明确导入归属证据的对象与受管字段；标题相似、label 相同不证明归属。读当前内容/版本并对比基线；人工变更、范围/目标变动、撤销即停止该目标。接口无原子比较写能力时不能声称锁住他人编辑；避免整体覆盖，写后再读回，竞争或不明结果记 conflict/unknown。

Jira 投递同样在每次副作用前实读 control_locator 的当前授权/控制状态；冻结 grant 不代表持续有效。发布数据/截图在内容冻结前脱敏，批准后的同步 child 不临时重写内容；发现敏感值则停止该目标，交回准备新的可审查版本。测试数据默认合成，不发布认证信息或生产数据。

每次调用每目标最多一次写入尝试，禁止自动循环。创建/链接/附件是独立目标动作，分别记账；某动作成功不重发。超时/结果未知先按已存对象 ID、原操作标记/内容摘要只读核实；不能确认唯一结果则保持 unknown，不直接再次 create。连接不支持稳定标识与可靠查重时只准备草稿，报告待人工确认。相同幂等键与内容已验证成功则 no-op；不同内容必须是新版本和新的适用批准。

收据保存实际远端 ID、source_version、expected_remote_hash、readback_ref、结果/时间/错误；记录摘要和完整证据分离。远端 Jira 更新无法保证不可篡改，固定批准/测试快照留可追溯附件或工程证据。GitLab 报告配置合适保留期限；过期/缺失链接不能作为当前 Gate 证据。JUnit 展示不是 job 通过依据，按 pipeline 协议核对真实退出状态及原报告。

## 恢复

failed/conflict/unknown 保留待办并停止该投递，不改变交付/Gate 状态。用户明确重试时仍核对原 method/workflow/快照/授权及实时撤销；升级不改内容、不扩范围。连接暂不可用不以新票替代旧票。撤销、关闭或角色改派停止新动作；已发生写入照实记录，不自动删除或回滚他人内容。Done/transition、生产发布、改权限均不属于本同步接口。
