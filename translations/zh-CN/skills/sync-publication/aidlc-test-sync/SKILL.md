# 用例、脚本与结果同步

父先读取 [同步协议](../../../workflow/testcase-sync.md)，区分 `同步用例` 与 `同步测试结果`，只加载本次目标、固定输入和 [同步回执](../../../templates/collaboration/sync-receipt.json)。按 [角色协议](../../../workflow/role-delivery.md) 派发独立执行者；子 Agent 使用冻结 [角色执行契约](../../../workflow/role-worker.md)。

- 用例同步：比较最后已同步基线和当前已批准版本，列受影响 Case ID、脚本与数据。未批准的编辑只报告差异；业务预期变化需 PO 确认。脚本更新交有文件范围授权的 Implement run，复用现有 TDD/测试能力并真实运行；无仓库时交 DEV 同步请求，不伪称代码已更新。
- 结果同步：绑定实际运行、Case 版本、候选、环境和证据，将摘要发布到授权的 Jira 执行记录；完整报告保留 GitLab。用例定义与每轮执行分开，失败和历史记录不覆盖。同步成功不代表测试或交付通过。

对归属冲突、撤销、版本漂移或结果未知按协议停止相关投递；重试先核实已有对象。首次运行不猜“已同步基线”。这是显式调用/继续时检查，没有常驻监听，也不自行注册 webhook、CI 任务或自动监控。
